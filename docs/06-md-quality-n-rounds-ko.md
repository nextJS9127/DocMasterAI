# 분석·정리된 MD 품질 향상 — N회차 반복 전략

## 전제

- **2회 LLM 구조**: 1차 = 원시 md → 분석·정리된 md, 2차 = 그 md → HTML.
- **핵심**: 1차 산출물(정리된 md)이 잘 나와야 사용자가 "문서 잘 만들었다"고 느낌. 현재는 품질이 들쑥날쑥함.
- **목표**: N회차 반복/정교화로 **상세하고 일관된** 정리 md를 만드는 방법 정리.

---

## 1. 품질이 들쑥날쑥한 이유 (단순화)

- **1회 생성에만 의존**: 한 번만 생성하고 검증·수정 단계가 없음.
- **역할·규칙만 있고 “품질 기준”이 약함**: 구체적인 채점 기준·체크리스트가 없으면 모델이 때로는 상세하게, 때로는 대충 출력함.
- **원본 누락/창작**: 원천 데이터를 빠뜨리거나, 없는 내용을 지어내는 경우를 잡아내지 않음.

---

## 2. N회차 반복·정교화 방안

### 방안 A: 실제 2~3회 LLM 호출 (Draft → Critique → Revise)

**흐름**

1. **1차 호출**: 원시 md → **초안(First Draft)** md.  
   지시: "필수 섹션을 모두 채우고, 원천 데이터에 있는 내용만 사용. 불확실한 부분은 [확인 필요]로 표시."
2. **2차 호출**: 입력 = 원시 md + 초안 md.  
   지시: "초안을 검토하라. 다음 관점에서만 짧게 답하라: (1) 원천 데이터에 있던데 초안에 빠진 핵심 사실이 있나? (2) 초안에 원천에 없는 창작·과장이 있나? (3) 각 필수 섹션이 구체적이고 실행 가능한가? 개선점을 bullet로만 나열하라."
3. **3차 호출**: 입력 = 원시 md + 초안 md + 2차에서 나온 개선점 목록.  
   지시: "개선점을 반영하여 초안을 수정하라. 출력은 개선점 설명 없이 **최종 정리된 마크다운만** \`\`\`markdown ... \`\`\` 블록으로 내보내라."

**장점**: 품질 상승 효과가 크고, 누락·창작을 줄이기 좋음.  
**단점**: 호출 2~3회 → 비용·지연 증가. UX에서 "1차 초안 → 검토 중 → 최종 반영" 단계 표시 필요.

---

### 방안 B: 1회 호출 안에서 “자가 검토 + 수정본” 출력 (Self-Critique in One Call)

**흐름**

- **한 번의 유저 메시지**에서 다음을 요구:
  1. **초안**: \`\`\`markdown ... \`\`\` (정리된 보고 md 초안).
  2. **자가 검토**: "위 초안을 다음 기준으로 검토하라. (1) 원천 데이터 대비 누락·과장 (2) 추상적 표현 여부 (3) 필수 섹션 완비도. 개선이 필요한 항목만 bullet로 나열."
  3. **최종안**: 개선점을 반영한 **최종 마크다운만** \`\`\`markdown ... \`\`\` 블록으로 한 번 더 출력.

파싱 시 **마지막** \`\`\`markdown ... \`\`\` 블록만 1차 산출물로 사용.

**장점**: 호출 1회, 비용·지연 부담 적음.  
**단점**: 한 응답에 담다 보니 토큰 한도·길이 제약 가능. 모델이 “검토 → 수정”을 제대로 할지는 모델 성능에 의존.

---

### 방안 C: 품질 루브릭 + (선택) 2차 호출 “루브릭 기준 개선”

**흐름**

1. **1차 호출** 시스템/유저 프롬프트에 **품질 루브릭**을 명시:
   - 예: "출력 전에 다음을 확인하라: □ Executive Summary가 2~4개 bullet인가 □ 원천에 없는 리스크·수치를 창작하지 않았는가 □ 각 섹션에 구체적 수치·대상·일정이 있는가 □ [확인 필요] 표시가 필요한 불명확한 부분에 붙였는가."
2. **선택적 2차 호출**: 1차 결과를 파싱한 뒤, "아래 마크다운을 위 루브릭에 맞춰 개선하라. 개선된 마크다운만 \`\`\`markdown ... \`\`\` 로 출력하라."  
   또는 **1차만** 쓰고, 프롬프트에 "루브릭을 충족하는지 스스로 점검한 뒤 그에 맞춰 수정한 최종안만 출력하라"고 넣어서 방안 B와 결합.

**장점**: 기준이 명확해져 들쑥날쑥함 감소. 2차 호출은 선택이라 비용 조절 가능.  
**단점**: 루브릭 설계·유지보수 필요.

---

### 방안 D: Few-Shot 예시 (좋은 정리 md 샘플)

**흐름**

- 시스템 또는 유저 메시지에 **1~2개의 예시**를 포함:
  - "[원시 데이터 예시] → [이에 대응하는 좋은 정리 md 예시]"
- "아래 [실제 원시 데이터]에 대해서도, 예시와 같은 수준·구조로 정리된 마크다운만 출력하라."

**장점**: 모델이 “어떤 수준이 좋은 것인지” 구체적으로 학습. 품질 분산 감소.  
**단점**: 토큰 사용 증가. 예시 선정·업데이트 필요.

---

### 방안 E: 구조화 출력 + 검증(선택)

**흐름**

- 1차에서 **고정 구조**(예: JSON)로 출력하게 하여 "필수 섹션 누락"을 코드로 검사.
  - 예: `{ "executiveSummary": "...", "keyChanges": [...], "processFlow": "...", "risks": "...", "actionItems": [...] }`
- 누락된 필드가 있으면 2차 호출: "아래 JSON에 누락된 필드 OOO를 원천 데이터에서 추려 채워 추가하라."

**장점**: 완비도 보장에 유리.  
**단점**: 사용자 프롬프트에서 섹션을 자유롭게 추가할 때는 스키마가 유연해야 함(새 필드 허용 등).

---

## 3. 조합 제안 (DocMaster 적용 시)

- **1차 품질 안정화**: **방안 C(루브릭)** + **방안 B(1회 호출 내 자가 검토·수정)**  
  - 프롬프트에 "품질 루브릭(체크리스트)"을 넣고, "초안 → 자가 검토 bullet → 루브릭 반영 최종 md"를 **한 번에** 출력하게 함.  
  - 파싱은 **마지막** \`\`\`markdown ... \`\`\` 블록만 1차 산출물로 사용.  
  - 비용·지연은 1회 호출로 유지.

- **품질을 더 올리고 싶을 때**: **방안 A(실제 2~3회 호출)**  
  - 설정 또는 "고품질 모드" 옵션으로 켜면: 1차 초안 → 2차 검토(비평) → 3차 최종 수정.  
  - 비용·시간이 늘어나는 대신 품질을 더 올릴 수 있음.

- **장기**: **방안 D(Few-Shot)**  
  - 경영진용/실무용 각 1개씩 “좋은 정리 md” 예시를 만들어 프롬프트에 포함.  
  - 루브릭만으로도 부족할 때 보조로 사용.

---

## 4. 요약

| 방안 | 호출 수 | 비용/지연 | 품질 기대 | 유연성(프롬프트·섹션 추가) |
|------|--------|-----------|-----------|-----------------------------|
| A. Draft→Critique→Revise | 2~3회 | 높음 | 높음 | 유지 |
| B. 1회 내 자가 검토+수정 | 1회 | 낮음 | 중~높음 | 유지 |
| C. 루브릭 + (선택) 2차 개선 | 1~2회 | 중간 | 중~높음 | 유지 |
| D. Few-Shot | 1회 | 중간(토큰↑) | 일관성↑ | 유지 |
| E. 구조화 출력+검증 | 1~2회 | 중간 | 완비도↑ | 스키마 유연화 필요 |

**핵심**: “분석 정리된 md가 잘 나와야 한다”는 전제하에, **루브릭(방안 C) + 1회 호출 내 자가 검토·수정(방안 B)** 부터 적용하고, 필요 시 **실제 N회 호출(방안 A)** 또는 Few-Shot(방안 D)을 추가하는 순서를 추천.

이 문서는 `docs/06-md-quality-n-rounds-ko.md` 로 두고, 1차 md 생성 프롬프트/파이프라인 설계 시 참고하면 됩니다.

---

## 5. 구현 반영 (코드)

- **고품질 체크박스**: Step 2 보고서 영역에 "고품질" 옵션 추가. 선택 시 N회차(초안→검토→수정) 적용.
- **일반 모드**: 루브릭 + 1회 호출 내 자가 검토·수정(초안 → 자가 검토 bullet → 최종 md).
- **2단계 파이프라인**: 기획서 기반 보고서(경영진/실무)는 항상 1차 정리 md 생성 → 2차 HTML 생성. (pptx는 기존 1회 호출 유지.)
- **HTML 형식만 변경 시**: 이미 정리 md가 있고 보고 유형(경영진/실무)이 같으면, 정리 md는 재생성하지 않고 **기존 정리 md를 기준으로 2차(HTML)만 재생성**함.
- **절대 준수**: 모든 프롬프트에 "중요 포인트와 핵심이 사라지거나 과도하게 축약되지 않게" 명시.
