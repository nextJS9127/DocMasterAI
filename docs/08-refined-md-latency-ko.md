# 정리 md 단계 지연 원인 및 화요일 버전과의 차이

## 화요일 버전과의 차이 (동작/코드)

| 항목 | 이전(화요일) | 현재 |
|------|--------------|------|
| **프롬프트** | 동일 | 변경 없음. `systemBase` + `MD_OUTPUT_INSTRUCTION_NORMAL`, `QUALITY_RUBRIC_AND_NO_LOSS` 등 그대로 사용. |
| **N회차** | 고품질 선택 시만 3회 호출 | 동일. 고품질 미선택 시 **1회 호출**만 수행. |
| **OpenAI reasoning_effort** | gpt-5.1/5.2에 `high` 고정 → 응답 느리고 본문 비어서 재시도 다수 | **고품질 선택 시에만** `high`, 일반 시 `none` → 1회 호출로 빠르게 응답 기대. |
| **재시도** | 없음 또는 적음 | **응답 본문이 비어 있으면** 1회 재시도 → 최대 **2배** 소요 시간. |
| **콘솔 로그** | 적음 | `[DocMaster] LLM 요청 시작/응답 완료`, `elapsedMs`, `didRetry`, `inputChars`/`inputLines` 추가. |

**요약:** 프롬프트 문구는 수정한 적 없고, N회차는 고품질일 때만 돌아가도록 그대로 두었음. 바뀐 것은 **reasoning_effort**와 **빈 응답 시 재시도**뿐.

---

## 느려질 수 있는 원인

1. **재시도 발생 (API 호출 2번)**  
   - 첫 응답이 비어 있으면 자동으로 1회 재시도.  
   - 콘솔에 `didRetry: true` 및 `[callLlm] OpenAI 응답 본문 비어 있음 — 1회 재시도` 로그가 찍힘.  
   - **대응:** 같은 요청이 2번 가므로 체감 시간이 약 2배. 첫 응답이 채워지도록 모델/옵션 확인 필요.

2. **원천 데이터(입력)가 매우 긺**  
   - `[DocMaster] 정리 md 1회 호출` 로그의 `inputChars`, `inputLines`가 크면 요청/응답 토큰이 많아져 API 처리 시간이 길어짐.  
   - **대응:** 입력 길이에 비례해 지연이 커지는 것은 정상. 필요 시 원천 문서를 잘라서 시험.

3. **API(OpenAI/클라우드) 측 지연**  
   - 네트워크/리전/부하로 첫 바이트까지 느려질 수 있음.  
   - **대응:** `elapsedMs`로 구간별 소요 시간 확인. 한 번 호출에 30초 이상이면 API/네트워크 이슈 가능성.

4. **고품질 선택 시 3회 호출**  
   - 고품질이면 초안 → 검토 → 수정으로 **3번** LLM 호출.  
   - **대응:** 의도된 동작. 일반 모드(1회 호출)와 비교해 약 3배 시간 소요 가능.

---

## 확인 방법 (브라우저 콘솔)

- `[DocMaster] 보고서 생성 시작` → `useTwoPhase: true` 이고, 고품질이 아니면 일반 모드.
- `[DocMaster] 정리 md 1회 호출 (일반 모드)` → `inputChars`, `inputLines` 확인 (입력 크기).
- `[DocMaster] LLM 요청 시작` → `highQuality: false` 인지 확인.
- `[DocMaster] LLM 응답 완료` → **`elapsedMs`**(몇 초 걸렸는지), **`didRetry`**(재시도 여부), **`bodyLength`**(본문 길이) 확인.

`elapsedMs`가 크고 `didRetry: true`이면 재시도 때문에 2배로 느린 것.  
`elapsedMs`만 크고 `didRetry: false`이면 입력이 크거나 API 자체가 느린 것.
