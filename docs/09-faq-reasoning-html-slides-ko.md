# FAQ: reasoning, HTML 생성, 슬라이드 수

## 1. OpenAI `reasoning_effort` — high vs none

- **`high`**  
  - gpt-5.1/5.2의 **thinking(사고) 기능**을 쓰는 옵션입니다.  
  - 모델이 응답 전에 내부적으로 “생각” 단계를 더 거치므로, 품질은 올라가고 **응답 시간·토큰은 늘어납니다.**  
  - 우리 코드에서는 **고품질(highQuality) 선택 시에만** `reasoning_effort: 'high'`를 넣습니다.

- **`none`**  
  - **확장 thinking을 쓰지 않는** 옵션입니다.  
  - 일반 채팅처럼 한 번에 답을 생성하므로 **더 빠르고**, Chat Completions에서 본문이 비는 문제도 줄어듭니다.  
  - 우리 코드에서는 **고품질 미선택 시** `reasoning_effort: 'none'`을 사용합니다.

정리: **high = gpt-5.1 thinking 사용**, **none = thinking 없이 일반 생성**.

## 2. HTML 입혀서 보고서 만들 때도 LLM을 쓰나?

**네. HTML 보고서도 LLM을 한 번 더 씁니다.**

흐름은 다음과 같습니다.

1. **정리 md 생성**  
   `generateRefinedMarkdownClient` → **callLlm 1회** (원시 md → 정리된 md).

2. **HTML 생성**  
   `generateHtmlFromMarkdownClient` → **callLlm 1회** (정리 md + 템플릿/스타일 가이드 → 완성 HTML 문자열).

즉, 2단계 파이프라인에서는 **정리 md용 1번 + HTML용 1번**, 총 **2번** LLM을 호출합니다. HTML은 템플릿 변수 채우기만이 아니라, **정리된 내용을 받아서 LLM이 HTML 전체를 생성**하는 구조입니다.

## 3. 보고서를 슬라이드 개수에 제한을 두는지

**아니요. 슬라이드 개수를 고정으로 제한하는 문구는 없고, 기본 템플릿 이상으로 늘려도 되도록 되어 있습니다.**

코드/프롬프트에서 확인된 내용:

- **기본 슬라이드를 채우고, 넘어가도 된다고 명시**
  - 예: "정리된 내용이 **기본 슬라이드에 다 담기 어렵거나 분량이 많으면:** **추가 슬라이드**를 … 넣어 모든 내용을 담을 것. **내용을 잘라 내지 말 것.**"
- **정해진 개수에 맞춰 잘라라 금지**
  - 예: "**내용을 잘라 내지 말 것.**", "Do not compress to fit a fixed number."
- **실무용은 슬라이드 수 제한 없음**
  - 예: "**실무용은 페이지/슬라이드 수 제한이 없다.** … 내용을 잘라 내거나 압축하지 말 것."

따라서 **슬라이드 개수를 고정으로만 만들라는 요구는 없고**, 내용이 많으면 추가 슬라이드를 넣으라고 되어 있습니다.
