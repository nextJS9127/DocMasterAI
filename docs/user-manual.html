1. 서비스 개요 및 전체 플로우

DocMaster AI는 PDF·PPTX 파일을 업로드하면, 문서에서 텍스트와 표를 추출하고, 선택한 유형에 맞춰 보고서·개발 피처 목록·테스트 케이스 등을 자동 생성하는 서비스입니다.

전체 사용 흐름

  1. 시작 전: 우측 상단 [Key 설정]에서 LLM API 키를 등록합니다.
  2. Step 1: 메인 화면에서 PDF 또는 PPTX 파일을 업로드합니다. 서버가 문서를 추출해 마크다운으로 변환합니다.
  3. Step 2: 만들고 싶은 문서 유형(기획서 기반 보고서 / 개발 피처 / 테스트 케이스)을 선택하고, 보고서 유형이라면 경영진용·실무용과 HTML 형식을 고른 뒤 [보고서 생성] 또는 [생성]을 누릅니다.
  4. 맞춤 질문 (선택): 기획서 기반 보고서를 처음 생성할 때, 정리 초안이 나온 뒤 **의도 반영용 질문**이 2~3개 뜨는 경우가 있습니다. 원하는 선택지를 고른 뒤 [반영하여 계속]을 누르면 해당 포인트를 강조·구체화한 최종 보고서가 만들어집니다. [건너뛰기]를 누르면 초안 그대로 HTML이 생성됩니다.
  5. 결과 확인: 생성이 끝나면 보고서 보기 팝업에서 HTML을 확인하고, HTML·정리 md 다운로드가 가능합니다.

설정 화면 정책

  • API 키와 설정은 브라우저 Local Storage에만 저장됩니다. 서버에 설정을 보내지 않습니다.
  • 보고서 생성 시에는 추출된 문서 내용(텍스트·표 등)만 선택한 LLM 제공업체 API로 전송됩니다. 원본 PDF/PPTX 파일은 추출 후 즉시 삭제되며 서버에 남기지 않습니다.

버튼·항목별 동작

항목/버튼동작
리포트 생성을 위한 LLM 선택드롭다운. OpenAI(GPT-5.2/5.1), Anthropic(Claude 4.6 Sonnet / 4.5 Opus), Google(Gemini 3.1 Pro / 2.5 Pro) 중 선택. 선택한 제공업체와 동일한 API 키를 사용해야 합니다.
API Key (필수)선택한 LLM 제공업체에서 발급한 API 키를 입력합니다. 저장 시 Local Storage에만 저장됩니다.
연결 확인현재 선택한 LLM과 입력한 키로 API 호출을 시도해, 정상 동작 여부를 확인합니다.
저장 및 적용LLM 선택 값과 API 키를 저장하고 모달을 닫습니다. 이후 보고서 생성 시 이 설정이 사용됩니다.
✕ (닫기)설정을 저장하지 않고 모달만 닫습니다.

그림 4. Step 1 — 업로드 영역

정책

  • 지원 형식: PDF, PPTX만 지원합니다. 그 외 파일은 업로드 시 안내 메시지가 나옵니다.
  • 처리 방식: 파일은 파싱 백엔드(로컬 또는 배포 서버)로 전송되어 텍스트·표가 추출됩니다. 추출이 끝나면 원본 파일은 즉시 삭제되며 서버에 보관하지 않습니다.

버튼·동작

동작설명
영역 클릭파일 선택 대화상자가 열립니다. PDF/PPTX를 선택하면 즉시 업로드·파싱이 시작됩니다.
드래그 앤 드롭파일을 업로드 영역 위에 놓으면 동일하게 업로드·파싱이 시작됩니다.
API 키 미등록 시Key 설정이 되어 있지 않으면 업로드 시도 시 토스트로 "API 키 등록이 필요합니다" 안내가 나오고, [Key 설정 열기] 또는 [도움말 보기]를 선택할 수 있습니다.

파싱이 진행되는 동안 "파이썬 서버가 문서를 추출 중입니다..." 메시지와 로딩 표시가 나타납니다. 완료되면 Step 2 영역이 나타납니다.

🔄 다른 파일 분석클릭 시 업로드 화면으로 돌아가 새 파일을 선택할 수 있습니다. 현재 추출 결과와 보고서는 초기화됩니다.

고품질 체크박스선택 시 N회차(최대 3회) 검토로 품질을 높입니다. LLM 호출이 2~3회 추가되어 비용과 시간이 늘어납니다.
📄 보고서 생성선택한 옵션(경영진/실무, HTML 형식, 고품질)으로 1단계: 정리 md 생성 후, 맞춤 질문이 생성되면 의도 반영 단계(아래 4.1)를 거친 뒤 2단계: HTML 생성을 진행합니다. 질문이 없거나 건너뛰면 곧바로 HTML이 생성됩니다. 생성 중에는 로딩 팝업이 표시되며, 완료 후 토큰·비용은 정리 md + HTML 생성 합산으로 표시됩니다.

생성이 완료되면 "보고서 생성이 완료되었습니다." 메시지와 함께 토큰 사용량(정리 md + HTML 생성 합산) 및 예상 비용이 표시되고, [만들어진 보고서 보기], 정리 내용 (.md) 다운로드 버튼이 나타납니다. 표시되는 토큰·비용은 1단계(정리 md)와 2단계(HTML 생성)의 합산입니다.

HTML 생성이 실패한 경우: 2단계(HTML 변환)에서 오류가 나도 1단계에서 생성된 정리 md가 있으면 해당 내용은 유지·표시되며, 「정리 내용 (.md) 다운로드」로 받을 수 있습니다. 이때 "HTML 보고서 생성에 실패했습니다. 정리된 내용(.md)은 아래에서 다운로드할 수 있습니다." 안내가 표시됩니다.

4.1 맞춤 질문 (의도 반영)

기획서 기반 보고서를 선택하고 [보고서 생성]을 누르면, 정리 초안이 만들어진 뒤 「맞춤 질문」 팝업이 뜨는 경우가 있습니다. 초안 내용을 바탕으로 "어떤 포인트를 강조·구체화할지" 2~3개의 다지선다 질문이 표시됩니다.

[ 스크린샷: 맞춤 질문 모달 — 질문 2~3개, 선택지, 건너뛰기 / 반영하여 계속 버튼 ]

그림 6-1. 맞춤 질문 모달

정책

  • 질문은 정리 초안에 실제로 등장하는 섹션·항목을 기준으로 생성됩니다. LLM이 초안을 분석해 JSON 형태로 질문을 만들며, 파싱이 실패하거나 질문이 0개면 이 단계는 건너뛰고 곧바로 HTML이 생성됩니다.
  • 같은 파일·같은 보고 유형(경영진 또는 실무)에서 HTML 형식만 바꿔서 재생성할 때는 정리 md를 다시 만들지 않고, 선택한 HTML 형식으로만 HTML이 다시 만들어집니다. 이때 맞춤 질문 단계도 다시 뜨지 않습니다. 새로 정리 md를 만들 때만(처음 생성하거나, 경영진↔실무를 바꾼 뒤 생성할 때) 질문이 나올 수 있습니다.

버튼별 동작

버튼/동작설명
각 질문의 선택지라디오 버튼 형태. 원하는 선택지를 하나씩 고르면 "반영하여 계속" 버튼이 활성화됩니다.
건너뛰기질문에 답하지 않고 초안 그대로 최종 HTML을 생성합니다. 로딩 후 보고서 보기로 넘어갑니다.
반영하여 계속모든 질문에 답한 뒤에만 클릭 가능합니다. 선택한 항목을 반영해 정리 md를 한 번 더 수정한 뒤, 그 결과로 HTML을 생성합니다. 의도에 맞게 강조·구체화된 보고서가 만들어집니다.
✕ (닫기)건너뛰기와 동일하게 동작합니다. 초안 그대로 HTML이 생성됩니다.
이용 팁: 보고서를 "의도에 맞게 더 잘" 만들고 싶다면, 맞춤 질문이 뜰 때 꼭 선택지를 골라 [반영하여 계속]을 누르세요. 리스크·결론·대안 비교 등 강조하고 싶은 부분을 선택하면 해당 섹션이 더 두드러지게 반영됩니다.

5. 보고서 보기 & 다운로드

[만들어진 보고서 보기]를 누르면 생성된 HTML 보고서가 팝업(또는 전체 화면)으로 표시됩니다. 보고서 HTML 안에 Mermaid 다이어그램 코드가 있으면 자동으로 다이어그램으로 렌더됩니다. HTML 생성이 실패했지만 정리 md가 있는 경우에는 해당 정리 md가 뷰어에 표시되거나, Step 2 패널에서 「정리 내용 (.md) 다운로드」로 받을 수 있습니다. 모델이 요청을 거절한 경우에는 안내 메시지와 함께 정리 md 다운로드가 권장됩니다.

[ 스크린샷: 보고서 뷰어 — 상단 헤더 + HTML 내용 영역 ]

Step 2 패널에서 정리 내용 (.md) 다운로드를 누르면, LLM이 생성한 정리 마크다운이 파일명_report.md로 다운로드됩니다.

8. 이용 팁

  • 처음 사용 시: 반드시 [Key 설정]에서 사용할 LLM과 API 키를 먼저 등록하고 [연결 확인]으로 동작을 확인한 뒤 업로드하세요.
  • 경영진용 vs 실무용: 경영진용은 1페이지 요약·결론·액션 중심으로 짧게, 실무용은 담당·일정·조건을 풍부하게 작성합니다. 기획서가 길면 실무용을 선택하는 것이 유리할 수 있습니다.
  • 고품질 옵션: 중요한 보고서는 "고품질"을 켜면 N회차 검토로 품질이 올라가지만, 생성 시간과 비용이 늘어납니다.
  • 추출 결과 보관: [추출 결과 다운로드 (.md)]로 원본 추출본을 보관해 두면, 나중에 같은 원본으로 다른 유형(경영진/실무/개발 피처 등)을 다시 만들 때 참고할 수 있습니다.
  • 정리 md 재활용: 같은 추출 결과·같은 보고 유형(경영진 또는 실무)에서 HTML 형식만 바꿔서 [보고서 생성]을 다시 누르면 정리 md는 재사용되고, 선택한 형식(기획/제안서 스타일, 프레젠테이션 스타일, 프리포맷)으로만 HTML이 다시 만들어집니다. 원하는 형태가 다르다면 «정리 내용 (.md)»을 다운로드해 두고 노션·위키·외부 도구에서 가공할 수도 있습니다.
  • 프롬프트 커스터마이즈: 팀에서 쓰는 용어나 필수 섹션을 맞추려면 [프롬프트 편집]에서 "필수 출력 항목" 등을 수정해 두면 됩니다.
  • 맞춤 질문 활용: 기획서 기반 보고서 생성 시 "맞춤 질문" 팝업이 뜨면, 강조하고 싶은 포인트를 선택한 뒤 [반영하여 계속]을 누르면 의도에 맞게 보강된 보고서가 만들어집니다. 질문이 안 뜨는 경우는 LLM이 질문을 만들지 못한 경우이며, 그때는 초안 그대로 HTML이 생성됩니다.
  • 오류 시: "503" 또는 과부하 메시지가 나오면 잠시 후 재시도하거나, [설정]에서 다른 LLM(예: OpenAI ↔ Claude)으로 바꿔 보세요.
  • 정리 md 보기: [정리 md 보기]로 열리는 뷰어에서는 마크다운 표가 테이블로, 목록은 단계별로 다른 블릿(●○■)으로 표시되며, Mermaid 코드 블록은 다이어그램으로 시각화됩니다.
  • 결과가 마음에 들지 않을 때: 다시 만들도록 지시해 주세요. 몇 번이고 다른 버전으로 만들어 드릴 수 있습니다.
  • 품질 변동: LLM 특성상 생성 결과물의 품질이 케바케로 다를 수 있습니다. 원하는 결과가 나올 때까지 계속 다시 시도해 보세요.

9. 정책 요약

항목내용
파일 보관업로드한 PDF/PPTX는 추출 완료 후 즉시 삭제되며, 서버에 원본을 보관하지 않습니다.
API 전송보고서 생성 시 추출된 텍스트·표 등만 선택한 LLM 제공업체(OpenAI, Anthropic, Google 등) API로 전송됩니다. 원본 파일 자체는 전송되지 않습니다.
설정 저장API 키, LLM 선택, 프롬프트 편집 내용은 브라우저 Local Storage에만 저장됩니다. 서버에 설정을 보내지 않습니다.
다운로드추출 결과(.md), 정리 내용(.md), HTML 보고서는 브라우저에서 생성·다운로드되며, 서버에 보고서 파일을 저장하지 않습니다.
